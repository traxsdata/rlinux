# Paths deliberately removed from rlinux ("Diet" and "Diet 2").
#
# Diet (issue #5): rlinux is an incremental C-to-Rust kernel port: a Rust
# module can only be built for an architecture that selects HAVE_RUST.  The
# 13 architectures in this list (plus their arch-only buses/drivers, sound
# boards and docs) cannot build Rust at all, so a driver converted to Rust
# can never compile or run there.  They were removed to cut ~1M lines of
# dead weight that costs review time and tree size.
#
# Diet 2 (issue #37, 2026-10-24): of the remaining eight architectures,
# only **x86, arm64, riscv and um** are targets for the desktop OS this
# project builds, so 32-bit arm, powerpc, s390 and loongarch (again: the
# arch trees, arch-only drivers, sound boards and docs) were removed too.
# Exception: the device-tree files that arch/arm64/boot/dts includes are
# kept (the arm64 default build compiles the device trees); the kept list
# is the transitive #include closure through
# scripts/dtc/include-prefixes/arm -> arch/arm/boot/dts.  The individual
# arch/arm entries below (instead of "arch/arm") exist exactly so the
# prune can be re-applied without deleting those kept files.  A second
# exception: the arch/arm files that the arm64 kernel itself builds are
# kept -- arch/arm/vdso/vdsomunge.c (the arm64 compat vDSO under
# CONFIG_COMPAT_VDSO builds the host-side vdsomunge from it) and the
# arch/arm/xen/*.c paravirt objects (enlighten, grant-table, p2m, mm)
# that arch/arm64/xen compiles for Xen PV guests.
#
# Supported architectures:
#   x86, arm64, riscv, um
#
# Syncing with upstream: when a future sync imports paths that were
# removed here, resolve the modify/delete conflicts by re-deleting them
# with:
#   grep -v -e '^#' -e '^$' scripts/rlinux/pruned-paths.txt | xargs git rm -r -q --ignore-unmatch
#
# The list is authoritative: anything under a path below stays deleted.
